## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline glyph gap, badge padding, terse suffix separation |
| sm | 8px | Compact action spacing, prompt field padding |
| md | 16px | Default overlay edge padding, row breathing room |
| lg | 24px | Section spacing between header/help/list regions |
| xl | 32px | Tabbar-to-overlay visual separation, prompt width rhythm |
| 2xl | 48px | Major inspector break inside full-tab overlays |
| 3xl | 64px | Reserved for large empty-state centering only |

Exceptions: Terminal-cell hit areas may snap to the existing row/column grid; do not add touch-style 44px buttons or floating-card padding that breaks Kaku density.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 15px | 400 | 1.28 |
| Label | 13px | 500 | 1.20 |
| Heading | 17px | 500 | 1.20 |
| Display | 24px | 500 | 1.10 |

Rationale: the compressed `13 / 15 / 17 / 24` scale is intentional for terminal-native density. Body and heading remain close so overlays preserve Kaku's compact tool feel instead of drifting into document-style UI spacing. DM Mono is the default family because its softer rhythm fits the intended dark operator mood better than JetBrains Mono while still preserving terminal clarity.

## Surface Inventory

| Surface | Role | Contract |
|---------|------|----------|
| Task Center overlay | Primary operator surface | Full-tab overlay, not a floating dialog or dashboard card. Must remain the main place to inspect unread, failed, running, and workspace-scoped state. |
| Tabbar metadata rail | Passive visibility | Continue compact unread and workspace-status surfacing inline with tab titles. Use it to advertise attention, not to host full workflows. |
| Shell menu + command palette | Discovery surface | Keep `Task Center` visible in native menus and palette so everyday actions are discoverable without CLI recall. |
| Prompt/confirm overlays | Editing and destructive actions | Use lightweight one-purpose overlays for metadata edits and confirmations. Do not introduce side panels, inspectors, or browser-like drawers. |

## Interaction Contract

1. The default operator path starts with `Task Center`, reached from `Shell -> Task Center`, command palette, or the existing `SUPER+SHIFT+J` shortcut.
2. Task Center must open as a full-tab overlay that preserves the surrounding Kaku frame. It must never present as a separate shell, dashboard, split view, or sidebar.
2a. The visual focal point is always the normalized result list, with the currently selected row acting as the immediate anchor for the eye.
3. The overlay header stays to three functional lines: title, active filters/query summary, and terse action help. Keep the body to a single normalized list below it.
4. Every result stays one row tall. No card stacks, secondary description blocks, or multi-line summaries in the default list.
5. Row content format stays compact and terminal-native: primary label first, then workspace/source/state suffixes inline, then metadata markers such as unread count, failed/running, rerun availability, status, and progress.
6. Keyboard behavior is first-class: typing filters immediately, `Backspace` edits the query, `Up/Down` changes selection, `Enter` focuses the selected target, `Esc` closes, `C` clears unread when available, `R` reruns or respawns when available.
7. Mouse behavior must match the keyboard path without introducing a separate model: single click selects a row, double click performs the primary action, and explicit inline icon or icon+label action targets may be clicked for clear unread, rerun/respawn, remain-on-exit style toggles, or metadata edit.
8. Do not depend on right-click context menus for the common path. The repo already notes window-layer context menus are not a reliable baseline, so common actions must remain reachable from overlay rows, the menubar, and keyboard shortcuts.
9. Metadata editing belongs in compact prompt-style overlays launched from the current workspace context. Use prefilled values, commit on `Enter`, cancel on `Esc`, and return focus to the previous terminal surface after completion.
10. Tabbar affordances are visibility rails, not workflow hubs. Clicking a tabbar operator marker may open Task Center prefiltered to the current workspace or current tab, but it must not expand into a browser-like side panel.
11. Hover is informative, not decorative. Only reveal actions or stronger contrast when the hovered row can actually perform that action.
12. State changes must feel event-driven and immediate. Clearing unread, focusing a target, or rerunning a pane should update the overlay snapshot in place without forcing a full-shell transition.

---

## Visual Contract

1. Preserve Kaku's dark, tool-like, workspace-centric tone from the shipped dark theme. Use `#15141b` as the visual anchor and step up to `#1f1d28` and `#29263c` only for active surfaces.
2. Selection emphasis should rely on reverse-video style, accent glyphs, or compact badges before introducing colored panels. Keep the terminal-grid feeling intact.
3. The tabbar remains minimal and compact. Unread and workspace metadata stay small inline suffixes or icon markers, never pill-heavy navigation chrome.
4. Prefer compact icons over raw punctuation markers for unread, progress, rerunnable, and failure state. Avoid bare text markers like `!` when a small icon communicates the state more cleanly. Icon+text pairs are welcome where clarity matters, but icon-only affordances are acceptable for repeated high-frequency actions.
5. Empty and error states should sit inside the same overlay canvas as ordinary content. No illustration screens, hero graphics, or promotional empty-state treatments.
6. Motion, if any, should be limited to existing overlay open/close behavior. Do not add animated drawers, spring transitions, or dashboard-style choreography.
